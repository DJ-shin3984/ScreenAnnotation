# Screen Annotation — 기획 및 구현 계획서 v2.1

Oct 14, 2026 · @JD

## 요약

**v2.0은 "켜는 순간 화면을 스크린샷처럼 정지시키고, 그 위에서만 판서하는" 모달 방식의 설치형 앱이다.** Ctrl+Shift+Space로 켜고 끈다. 켜져 있는 동안 하위 프로그램은 조작하지 않으므로 마우스·키보드·휠을 전부 판서용으로 쓸 수 있다.

| 구분 | v1.x (이전) | v2.0 (현재) |
| --- | --- | --- |
| 기본 동작 | 라이브 화면 위 판서, 평소엔 클릭 투과 | 켜면 화면 정지 → 정지 화면 위 판서 |
| 켜기/끄기 | 판서 모드 ↔ 일반 모드 전환 | Ctrl+Shift+Space 토글 (꺼지면 오버레이 자체가 사라짐) |
| 기본 도구 | 지정 없음 | 펜 |
| 마우스 휠 | 하위 앱 스크롤 | 굵기 조절 / Ctrl+휠은 확대·축소 |
| 도구 전환 | 툴바 클릭 | Tab: 펜 → 형광펜 → 도형 / Shift+Tab: 현재 도구의 변형 순환 |
| 화면 요소 | 없음 | Ctrl+클릭으로 이미지·텍스트를 객체로 떼어내 이동 |
| 클릭 투과·키 훅 | 핵심 기능 | **불필요** (켜진 동안은 앱이 입력을 독점) |

이 전환으로 v1.2의 가장 큰 리스크였던 클릭 투과·포커스 충돌·라이브 화면 성능 문제가 대부분 사라진다. 대신 **Ctrl+클릭 요소 인식**이 이 제품의 핵심 차별 기능이자 가장 어려운 부분이 된다.

## 조작 체계

**전역으로 등록하는 키는 Ctrl+Shift+Space 하나뿐이고, 나머지는 켜진 동안 오버레이 창 안에서만 동작한다.** 그래서 다른 프로그램의 단축키와 충돌하지 않는다.

### 키·마우스 맵 (확정)

| 입력 | 동작 |
| --- | --- |
| Ctrl+Shift+Space | 켜기(화면 정지 + 펜) / 끄기(판서가 있으면 저장 여부 확인) |
| 좌클릭 드래그 | 현재 도구로 그리기 |
| 우클릭 | **팔레트 열기** — 펜 계열·형광펜: 색상 팔레트 / 도형: 도형 종류 팔레트 |
| 휠 | 현재 도구 굵기 조절 |
| Ctrl+휠 | 커서 기준 확대·축소 |
| Tab | 도구 순환: 펜 → 형광펜 → 도형 |
| Shift+Tab | 현재 도구의 변형 순환 |
| Ctrl+클릭 | 화면 요소(이미지·텍스트) 선택 |
| T / 빈 곳 더블클릭 | 텍스트 입력창 |
| Esc | **기본 상태로 복귀**: 진행 중 작업 취소, 선택·입력창 해제, 도구를 일반 펜으로. 앱은 꺼지지 않음 |
| Ctrl+Z / Ctrl+Y | Undo / Redo |
| Delete | 선택 객체 삭제 |
| 1\~9 | 색상 바로 선택 (팔레트와 같은 순서) |
| E | 지우개 켜기 (토글). 다시 E → 직전 도구로 복귀, Esc → 일반 펜 |
| Ctrl+0 | 확대 원래대로 |
| 가운데 버튼 드래그 / Space+드래그 | 확대 상태에서 화면 이동 |
| Ctrl+드래그 | 영역 OCR → 글자 복사 |
| Alt+드래그 (선택 요소) | 요소 복제 |
| Ctrl+S / Ctrl+C | 판서 포함 PNG 저장 / 클립보드 복사 |

Esc는 확대 배율과 도구별 색·굵기 설정은 건드리지 않는다. "지금 무엇을 하고 있든 깨끗한 펜 상태로"만 되돌린다.

### 색상 팔레트

| 번호 | 색 | 값 |
| --- | --- | --- |
| 1 | 빨강 | #FF3B30 |
| 2 | 주황 | #FF9500 |
| 3 | 노랑 | #FFCC00 |
| 4 | 초록 | #34C759 |
| 5 | 파랑 | #007AFF |
| 6 | 남색 | #3F51B5 |
| 7 | 보라 | #AF52DE |
| 8 | 흰색 | #FFFFFF |
| 9 | 검정 | #000000 |

- 펜 계열·형광펜에서 우클릭한 지점에 9칸 **원형 팔레트**가 뜬다. 우클릭을 누른 채 원하는 색 방향으로 끌었다 떼면 선택, 짧게 우클릭 후 색을 클릭해도 선택된다.
- 색은 도구별로 기억한다 (펜은 빨강, 형광펜은 노랑처럼). 기본값은 펜 빨강, 형광펜 노랑, 도형 빨강.
- 레이저 포인터도 이 색을 쓴다. 흰색·검정은 어두운/밝은 화면 어디서든 보이게 하려는 용도다.

### 도형 팔레트

도형 도구에서 우클릭하면 같은 방식의 원형 팔레트에 **도형 종류**가 뜬다. 도형의 색은 숫자 1\~9 키로 고른다.

| 순서 | 도형 | 그리는 방법 | Shift |
| --- | --- | --- | --- |
| 1 | 사각형 | 대각선 드래그 | 정사각형 |
| 2 | 삼각형 | 드래그 상자에 맞춘 이등변삼각형 (꼭짓점 위) | 정삼각형 |
| 3 | 원 | 드래그 상자에 내접하는 타원 | 정원 |
| 4 | 원기둥 | 드래그 상자 안에 윗면 타원 + 양옆 세로선 + 아랫면 앞쪽 반타원 (뒤쪽은 점선) | 윗면을 원에 가깝게 |
| 5 | 화살표 | 시작점 → 끝점 | 45° 단위 |
| 6 | 직선 | 시작점 → 끝점 | 45° 단위 |

- 팔레트 칸은 6개로 시작하고, 도형은 `ShapeKind`에 추가하는 방식으로 늘릴 수 있게 한다 (예: 둥근 사각형, 말풍선).
- Shift+Tab 순환도 이 표 순서를 따른다.

### 끄기와 저장

- 판서가 하나도 없으면 묻지 않고 바로 끈다.
- 판서가 있으면 화면 가운데에 작은 확인창: **저장(Enter) / 버리기(N) / 계속 판서(Esc)**
- 저장 = 지금 보이는 정지 화면 + 판서를 원래 배율(1×)로 합성한 PNG. 저장 순간 남아 있는 사라지는 펜 획도 포함한다.
- 확인창이 떠 있을 때 Ctrl+Shift+Space를 한 번 더 누르면 버리고 바로 끈다 (빠르게 끄고 싶을 때).
- 저장하지 않은 판서는 다시 열 수 없다.

화면 우측 하단에 **현재 도구·변형·굵기·색을 보여 주는 작은 HUD**를 둔다. 키보드로만 바꾸는 구조라, 지금 무엇이 선택돼 있는지 보이지 않으면 헷갈린다.

## 활성화 수명주기

**한 번의 켜기\~끄기가 하나의 "보드"다.** 판서 보드 안에서는 요소 선택과 텍스트 입력이 잠깐 들어갔다 나오는 하위 상태이고, 끄는 순간 저장 여부를 묻고(저장 시 정지 화면+판서 PNG, 아니면 버림) 원래 쓰던 창으로 포커스가 돌아간다.

## 도구와 변형

**도구는 2단계로 고른다: Tab은 "무엇으로"(펜·형광펜·도형), Shift+Tab은 "어떤 방식으로"(그 도구의 변형).** 각 도구는 마지막으로 쓴 변형·굵기·색을 기억해서, Tab으로 돌아오면 그대로 복원된다.

### 변형 순환표

| 도구 (Tab) | Shift+Tab 순환 | 비고 |
| --- | --- | --- |
| 펜 | 일반 펜 → 사라지는 펜 → 레이저 포인터 | 사라지는 펜: 손을 뗀 뒤 2.5초 유지, 0.5초 동안 서서히 사라짐. 레이저: 획을 남기지 않고 커서에 빛나는 점 + 0.3초 꼬리 |
| 형광펜 | 자유 형광펜 → 직선 형광펜 | 직선 형광펜: 수평에 가까우면 자동 수평 정렬. 글자 줄 강조용 |
| 도형 | 사각형 → 삼각형 → 원 → 원기둥 → 화살표 → 직선 | 우클릭 도형 팔레트로 바로 선택도 가능. Shift 드래그 규칙은 도형 팔레트 표 참고 |

기본 상태(켜질 때, Esc 후)는 **펜 / 일반 펜**이다.

### 사라지는 펜의 규칙

- 획은 Undo 이력에 **넣지 않는다**. 스스로 사라지는 것을 Undo하면 이상하게 동작하기 때문이다.
- 그리는 중에는 사라지지 않는다. 연속으로 여러 획을 그리면 **마지막 획을 뗀 시점부터** 한꺼번에 2.5초를 센다(문장 하나를 다 쓸 때까지 남아 있게).
- 유지 시간(1\~10초)은 설정에서 바꿀 수 있다.
- Ctrl+S·Ctrl+C 시점에 보이는 사라지는 획은 결과 이미지에 포함한다.

### 휠 굵기

| 도구 | 범위 | 단계 |
| --- | --- | --- |
| 펜 | 1\~40 px | 1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 40 |
| 형광펜 | 8\~64 px | 8, 12, 16, 24, 32, 48, 64 |
| 도형 선 | 1\~16 px | 1, 2, 3, 4, 6, 8, 12, 16 |

얇을 때는 촘촘하게, 두꺼울 때는 크게 바뀌도록 **고정 단계표**를 쓴다. 같은 휠 한 칸이라도 1→2px와 32→40px의 체감이 비슷해진다. 정밀 터치패드처럼 휠 값이 잘게 들어오는 장치는 누적해서 120 단위마다 한 단계씩 바꾼다.

### Ctrl+휠 확대

- 배율 1×\~8×, 휠 한 칸에 1.25배, **커서 아래 지점이 고정**되도록 확대한다.
- 확대 시 정지 화면은 원본 캡처 해상도 이상으로 선명해지지 않는다. 4K 화면을 4×로 키우면 픽셀이 보이는 것이 정상이며, 판서(벡터)는 확대해도 선명하다.
- 확대 상태에서 그린 획의 굵기는 **화면에 보이는 굵기 기준**으로 저장한다(8× 확대 중 4px 펜 = 원본 좌표 0.5px). 확대해서 세밀하게 쓰는 용도에 맞춘 선택이다.

## Ctrl+클릭 요소 선택

**정지된 화면은 그냥 이미지지만, 그 아래의 실제 프로그램은 아직 살아 있다. 그래서 1차로 Windows UI Automation(UIA)에 "이 위치에 무엇이 있었는지" 묻고, 실패하면 2차로 스크린샷 이미지를 분석한다.** 화면이 정지된 동안 사용자는 하위 프로그램을 조작하지 않으므로, UIA가 알려 주는 위치와 스크린샷이 거의 일치한다.

### 사용자 경험

1. Ctrl을 누르고 있으면 커서 아래 인식된 요소에 **점선 테두리 미리보기**가 뜬다 (개발자 도구의 요소 검사와 같은 방식)
2. Ctrl+클릭 → 그 요소가 선택되어 조절 핸들이 붙는다 (PPT 그림 선택과 같음)
3. 같은 위치를 다시 Ctrl+클릭 → 한 단계 큰 범위로 확장 (텍스트: 단어 → 줄 → 문단 / 이미지: 이미지 → 이미지를 감싼 영역)
4. 드래그 → 이동 (원래 자리는 배경으로 메움) / Alt+드래그 → 복제 / 모서리 핸들 → 비율 유지 크기 조절
5. 텍스트 요소 선택 중 Ctrl+C → 그 **글자 자체**를 복사, Delete → 화면에서 지움(배경으로 메움)

### 인식 파이프라인

| 단계 | 주체 | 방법 | 결과 |
| --- | --- | --- | --- |
| 1. 대상 창 찾기 | 앱 | 켜질 때 저장해 둔 창 목록 스냅샷(Z-order, 위치)에서 클릭 지점을 포함한 가장 위 창 | 창 핸들 |
| 2. UIA 질의 | Windows OS (UIA) + 하위 앱 | 그 창의 UIA 트리에서 클릭 지점을 포함하는 가장 깊은 요소. 시간 상한 150ms | 요소 종류, 경계 사각형, 텍스트 |
| 3. 텍스트 범위 | 하위 앱 (TextPattern 지원 시) | `RangeFromPoint` → 단어/줄/문단 단위 확장 | 정확한 글자 + 줄별 사각형 |
| 4. 검증 | 앱 | UIA 사각형이 클릭 지점을 포함하고, 창 전체·화면 전체 크기가 아닌지 확인 | 통과 / 2차로 |
| 5. 2차: 텍스트 | 앱 | 클릭 주변 영역 OCR → 단어 상자 → 줄·문단으로 묶기 | 근사 글자 + 사각형 |
| 6. 2차: 이미지 | 앱 | 클릭 주변 배경색 추정 → 배경과 다른 픽셀의 연결 영역(팽창 후) 중 클릭 지점 포함 영역 | 사각형 |

1단계에서 UIA에 화면 좌표로 바로 물으면(`ElementFromPoint`) 맨 위에 있는 오버레이 자신이 잡힌다. 그래서 창 목록 스냅샷에서 대상 창을 먼저 고른다. (대안: 질의 순간만 오버레이를 투과 상태로 바꾼 뒤 `ElementFromPoint` — M1 PoC에서 둘 다 측정해 빠른 쪽 채택)

### 앱 종류별 예상 정확도

| 하위 앱 | UIA 1차 성공 예상 | 비고 |
| --- | --- | --- |
| Word·메모장·VS Code·탐색기 | 높음 | 글자 단위 TextPattern 지원 |
| Chrome·Edge 웹페이지 | 높음 | 이미지(`img`)·문단 구분 잘 됨. 처음 질의 때 접근성 트리 생성으로 수백 ms 지연 가능 |
| PowerPoint 편집 화면 | 중간 | 도형·그림 단위는 나오나 슬라이드쇼에서는 슬라이드 전체 한 덩어리 |
| PDF 뷰어·이미지 뷰어 | 낮음 | 2차(이미지 분석·OCR)에 의존 |
| 원격 데스크톱·화상회의 화면 공유·게임 | 없음 | 화면이 그림 한 장이므로 2차만 가능 |

### 떼어낸 요소의 처리

- 선택된 요소는 **정지 화면에서 잘라낸 비트맵 + 원래 위치 + 종류(이미지/텍스트) + 글자(알면)** 로 이루어진 `ElementAnnotation` 객체가 된다.
- 처음 이동하는 순간 원래 자리에 **"구멍 메움" 패치**를 함께 만든다. 기본은 요소 테두리 바깥 2px 띠의 대표색으로 채우기이며, 그라데이션·사진 배경처럼 단색이 아니면 결과가 어색할 수 있다(개선안: 이미지 복원 알고리즘, Advanced).
- 이동·크기 조절·삭제는 모두 Command로 기록되어 Undo가 된다. 단순 선택은 기록하지 않는다.

## 설계 검토

**모달 방식은 기술적으로 v1.x보다 훨씬 쉽고 안정적이다.** 가장 큰 이득은 오버레이가 투명 창일 필요가 없어진다는 점이다. 정지 화면을 배경으로 직접 그리므로 일반 불투명 창이 되고, WPF가 GPU 가속을 그대로 쓴다. v1.2의 1순위 리스크(4K 투명 창 성능)가 사라진다.

### 사라진 리스크

| v1.2 리스크 | 사라진 이유 |
| --- | --- |
| 투명 창 렌더링 성능 | 불투명 전체 화면 창 + 정지 화면 배경 |
| 클릭 투과·포커스 충돌 | 켜진 동안은 앱이 입력 독점, 꺼지면 창이 숨겨짐 |
| 저수준 키 훅 | 오버레이가 활성 창이라 일반 키 이벤트로 충분 |
| 캡처 시 자기 자신 촬영 | 켜기 직전(오버레이가 없을 때) 한 번만 캡처, 저장 이미지는 앱 데이터로 직접 합성 |
| Freeze 판서와 라이브 판서 분리 | 모든 판서가 정지 화면 위에서만 일어남 |

## 렌더링 파이프라인 구현 설계

**완성된 판서는 캐시된 비트맵으로, 그리는 중인 획만 매 프레임 다시 그린다.** 이것이 240Hz에서 16ms를 지키는 핵심이다.

### 레이어와 갱신 주기

| 레이어 | 내용 | 갱신 시점 | 구현 |
| --- | --- | --- | --- |
| L1 정지 화면 배경 | 캡처 이미지 | 켜질 때 1회 | `ImageBrush` 1장 |
| L2 Annotation | 확정된 펜·도형·텍스트 | 객체 추가·삭제·Undo 때만 | `DrawingVisual` 묶음을 `RenderTargetBitmap`에 캐시, 변경 시 해당 영역만 재합성 |
| L3 Live Stroke | 그리는 중인 획·도형 미리보기 | 포인터 이동마다 | 단일 `DrawingVisual`, `StreamGeometry` 재생성 |
| L4 Interaction | 선택 박스·핸들 | 선택 변경 시 | 별도 `DrawingVisual` |

### 펜 획 처리 흐름

1. 포인터 Down → `LiveStroke` 생성, 시작점 기록 (모니터 로컬 물리 픽셀)
2. Move → 점 추가. 직전 점과 1px 미만 차이는 버림 (점 수 절감)
3. 렌더 프레임마다 L3만 다시 그림. 곡선은 Catmull-Rom → 베지어 변환으로 부드럽게
4. Up → 점 단순화(Ramer–Douglas–Peucker, 허용오차 0.5px) → `PenStroke` 확정 → `AddAnnotationCommand` 실행 → L2 해당 영역 재합성 → L3 비움

### 좌표 변환 (v1.1 유지)

저장은 모니터 로컬 물리 픽셀, 표시 직전에만 DIP로 변환한다. 오버레이 루트에 `ScaleTransform(96/dpiX, 96/dpiY)` 하나를 걸어 두면 모든 레이어가 물리 픽셀 좌표로 그려진다. DPI가 바뀌면 이 변환 하나만 교체한다.

```latex
x_{DIP} = (x_{global} - x_{monitor}) \times \frac{96}{DPI_x}
```

### 렌더 백엔드 추상화

```csharp
public interface IOverlayRenderer
{
    void SetFreezeBackground(BitmapSource? image);
    void InvalidateAnnotations(Rect dirtyPx);   // L2 부분 재합성
    void UpdateLiveStroke(LiveStroke? stroke);  // L3
    void SetSelection(SelectionState? state);   // L4
    void SetDpi(double dpiX, double dpiY);
}
```

1단계는 `WpfOverlayRenderer`로 구현한다. PoC에서 4K 연속 판서 P95가 16ms를 넘으면 `D2DOverlayRenderer`(Vortice.Direct2D1 + DirectComposition)를 같은 인터페이스로 추가한다. 상위 모듈은 바뀌지 않는다.

### 확대 뷰와 굵기 미리보기

- Ctrl+휠 확대는 정지 화면과 판서 전체에 **뷰 변환(Scale + Translate) 하나**를 거는 방식이다. 판서 좌표는 원본 화면 픽셀 그대로 저장되므로, 확대 상태에서 그린 획도 축소하면 정확한 위치에 남는다.
- 확대 중 이동은 가운데 버튼 드래그 또는 Space+드래그로 처리한다.
- 휠로 굵기를 바꾸는 동안 커서 위치에 **굵기 원 미리보기**를 0.8초간 L4에 표시한다.

## 데이터 모델·히스토리·세션

**한 번 켜고 끄는 단위를 "보드(Board)" 하나로 본다.** 보드 = 모니터별 정지 화면 + 그 위의 판서 객체 + Undo 이력. 끄면 보드는 버려지고, 저장을 고른 경우에만 합성 PNG가 남는다.

### 모델

```csharp
public sealed record Board(
    Guid Id, DateTimeOffset CapturedAt,
    IReadOnlyList<BoardMonitor> Monitors);           // 모니터별 정지 화면 경로·크기·DPI

public abstract record Annotation
{
    public required Guid Id { get; init; }
    public required string MonitorKey { get; init; }
    public required long Order { get; init; }         // 전역 생성 순서
    public required RectPx Bounds { get; init; }      // 원본 화면 픽셀 기준
}

public sealed record PenStroke(...)       : Annotation; // Kind = Pen | Highlighter | StraightHighlighter
public sealed record ShapeAnnotation(...) : Annotation; // Rect | Triangle | Ellipse | Cylinder | Arrow | Line
public sealed record TextAnnotation(...)  : Annotation; // 문자열, 글꼴, 크기, 색
public sealed record ElementAnnotation(
    ElementKind Kind,            // Image | Text
    string CropPath,             // 정지 화면에서 잘라낸 비트맵
    RectPx SourceRect,           // 원래 위치
    string? Text,                // UIA/OCR로 얻은 글자
    ElementSource Source         // Uia | Ocr | ImageAnalysis
) : Annotation;
public sealed record PatchAnnotation(RectPx Area, string FillColor) : Annotation; // 구멍 메움
```

사라지는 펜 획은 `Annotation`이 아니다. 렌더러가 별도로 관리하는 **임시 목록**(`EphemeralStroke`: 점 목록 + 만료 시각)에만 존재하고, 저장·Undo 대상이 아니다.

### 명령

| 명령 | 사용처 | Undo 동작 |
| --- | --- | --- |
| Add | 펜·형광펜·도형·텍스트 확정 | 제거 |
| Remove | 지우개, Delete | 복원 |
| Replace | 도형 보정, 텍스트 재편집, 요소 이동·크기 조절 | 원래 값 |
| LiftElement | 요소를 처음 움직일 때 (Element + Patch를 한 번에 추가) | 둘 다 제거 → 원래 화면 그대로 |
| Composite | 전체 지우기 | 역순 Undo |

히스토리는 보드당 전역 단일 스택(200단계). 보드를 닫으면 히스토리도 끝난다.

### 저장

| 항목 | 결정 |
| --- | --- |
| 저장 시점 | 끌 때 확인창에서 "저장"을 고른 경우, 또는 켜진 동안 Ctrl+S |
| 저장물 | 정지 화면 + 판서 합성 PNG 1장 (모니터별 파일, 설정에서 한 장으로 이어붙이기 가능) |
| 위치 | 기본 `사진\ScreenAnnotation\`, 파일명 `날짜_시간_모니터.png`, 설정에서 변경 |
| 판서 벡터 데이터 | 저장하지 않음. 끄면 보드는 메모리에서 사라짐 |
| 비정상 종료 | 판서 복구 없음. 워치독은 화면을 다시 쓸 수 있게 만드는 것만 담당 |
| 설정 | `%APPDATA%\ScreenAnnotation\settings.json` (단축키, 도구별 색·굵기, 사라지는 시간, 저장 위치) |

## 캡처·OCR·도형 보정

**캡처는 켜는 순간 한 번뿐이다.** 그 뒤의 저장·복사·확대·요소 잘라내기는 모두 그 한 장과 앱이 가진 판서 데이터로 만든다. 화면을 다시 찍지 않으므로 v1.x의 "자기 자신 촬영" 문제가 없다.

### 켜기 시 캡처

1. 앱: 핫키 수신 즉시 창 목록 스냅샷(UIA용) 저장
2. 앱: 모니터별 병렬 캡처 — 1순위 DXGI Desktop Duplication(지연이 가장 짧음), 실패 시 `Windows.Graphics.Capture`, 최후 GDI `BitBlt`
3. 앱: 캡처가 끝난 모니터부터 오버레이 표시 (모니터 간 정지 시점 차이는 수십 ms 이내 목표)
4. 목표: 단축키 → 모든 모니터 정지 화면 표시 P95 150ms

### 결과물

| 기능 | 방법 |
| --- | --- |
| Ctrl+S | 정지 화면 + 판서를 원본 해상도로 합성 → PNG (모니터별 또는 전체 이어붙임, 설정) |
| Ctrl+C | 같은 합성본을 클립보드로. 텍스트 요소가 선택돼 있으면 글자를 복사 |
| 끌 때 | 판서가 있으면 저장 여부 확인 → 저장 시 Ctrl+S와 같은 합성 PNG, 아니면 버림 |

### OCR의 역할

v2.0에서 OCR은 독립 기능이라기보다 **Ctrl+클릭 텍스트 인식의 2차 경로**다. UIA가 글자를 주지 못하는 화면(PDF, 원격 화면, 이미지 속 글자)에서 쓰인다.

- 엔진: `IOcrService` 인터페이스 — 1차 `Windows.Media.Ocr`(한국어 OCR 언어팩 필요), 대체 ONNX 계열 모델(첫 사용 시 로딩)
- 범위: 클릭 지점 주변 영역만 잘라서 인식(전체 화면 인식보다 빠름), 결과를 단어 → 줄 → 문단으로 묶어 Ctrl+클릭 반복 확장에 사용
- 원래 15개 기능의 "OCR 영역 지정 후 텍스트 추출"은 Ctrl+드래그(영역 선택) → 글자 복사로 유지 (확정)

### 도형 자동 보정

도형 도구가 따로 있으므로 보정은 **펜으로 대충 그린 것을 정리하는 용도**다. 획 끝에서 버튼을 누른 채 0.5초 멈추면 보정, 그냥 떼면 원본 유지 — 손을 멈추는 동작으로 의도를 구분한다(iPad 메모와 같은 방식). 판정 기준은 v1.2와 동일하다.

- 직선: 시작–끝 직선과 모든 점의 최대 거리 < 획 길이의 4%
- 사각형: 단순화 후 꼭짓점 4\~5개 + 닫힘 + 모서리 각 70°\~110°
- 타원: 닫힘 + 중심 거리 변동계수 < 0.15

## 솔루션 구조와 핵심 클래스

**의존 방향은 한 방향이다: 모든 모듈이 Core를 바라보고, Core는 아무것도 참조하지 않는다.** v1.1 구조에 Watchdog 프로젝트 하나를 추가했다.

App만 모든 프로젝트를 참조해 조립한다. Core 단위 테스트는 Windows 없이 돌아간다.

| 프로젝트 | 핵심 클래스 | 책임 |
| --- | --- | --- |
| Core | `ModeController`, `AnnotationStore`, `HistoryManager`, `IAnnotationCommand` | 상태 전환 규칙, 판서 데이터, Undo/Redo |
| Windows | `MonitorService`, `OverlayHost`, `HotkeyService`, `WindowSnapshot, UiaElementLocato``r`, `CaptureService` | Win32 P/Invoke 전부. 다른 프로젝트는 `DllImport` 금지 |
| Rendering | `WpfOverlayRenderer`, `StrokeBuilder`, `GeometryFactory` | 레이어 렌더, 곡선 보간, 점 단순화 |
| Recognition | `WindowsMediaOcrService`, `ShapeRecognizer`, ImageRegionDetector | OCR, 도형 판정, 이미지 요소 영역 추출(UIA 실패 시) |
| Storage | `SessionRepository`, `SettingsRepository` | JSON 직렬화, 원자적 저장, 손상 격리 |

| Watchdog | `HeartbeatMonitor` | Named Pipe 하트비트 수신, 무응답 시 오버레이 강제 투과 |

### 기술 결정

- **.NET 8 LTS** (`net8.0-windows10.0.19041.0`) — WinRT 캡처·OCR API를 CsWinRT로 직접 사용
- **DPI**: 앱 매니페스트에 `PerMonitorV2`
- **DI**: `Microsoft.Extensions.DependencyInjection`
- **MVVM**: CommunityToolkit.Mvvm
- **P/Invoke**: CsWin32 소스 생성기 (선언 수작업 오류 방지)
- **JSON**: System.Text.Json 소스 생성 모드

## 마일스톤·게이트·테스트

**M1에서 "켜기 150ms"와 "UIA로 요소 찾기" 두 가지를 동시에 검증한다.** 판서 자체는 기술 위험이 낮고, 제품의 성패는 켜는 속도와 Ctrl+클릭 품질에 달려 있기 때문이다.

1. **M1 — 켜기·끄기 PoC + 요소 인식 PoC**
   - 범위: 전역 핫키, 모니터별 병렬 캡처, 전체 화면 오버레이 표시·숨김, 포커스 반환, 워치독 / Ctrl+클릭 → UIA로 사각형 표시만 (이동 없음)
   - 게이트: 켜기 P95 150ms (4K+FHD) / 끄면 이전 창에 입력이 정상 복귀 / UI 스레드 강제 정지 시 3초 내 화면 복구 / Chrome·Word·VS Code에서 이미지·문단 사각형이 맞게 잡히는 비율 측정
2. **M2 — 판서 엔진**
   - 범위: 펜·형광펜·도형 6종·도형 팔레트, Tab/Shift+Tab, 휠 굵기, HUD, 우클릭 색상 팔레트, 사라지는 펜, 레이저 포인터, 지우개, Undo/Redo
   - 게이트: 연속 판서 입력→표시 P95 16ms, 휠·Tab 반응 즉시(다음 프레임)
3. **M3 — 확대·텍스트·멀티 모니터**
   - 범위: Ctrl+휠 확대·이동, 텍스트 입력창(한글 IME), 혼합 DPI
   - 게이트: 확대 8×에서 그린 획이 축소 후 위치 오차 1px 이내, 한글 조합 중 Enter·Esc·Tab 오동작 0건
4. **M4 — 요소 조작 (Core 완료)**
   - 범위: 요소 이동·복제·크기 조절, 구멍 메움, 단계 확장(단어→줄→문단), 텍스트 복사
   - 게이트: 대표 화면 30종(웹·문서·IDE·PPT)에서 원하는 요소가 3번 이내 Ctrl+클릭으로 잡히는 비율 80% 이상
5. **M5 — 저장·보드·2차 인식**
   - 범위: Ctrl+S/C, 끄기 시 저장 확인창, OCR·이미지 분석 2차 경로, 도형 보정
   - 게이트: 저장 중 강제 종료 50회 손상 0건, PDF·원격 화면에서 텍스트 요소 인식 동작
6. **M6 — 출시**
   - 범위: 설정 화면(핫키·색·사라지는 시간), 설치 프로그램·자동 시작·트레이, 코드 서명, 화면 공유 호환 확인

**Claude Code CLI에 이 계획서 링크를 주고 직접 참조하게 한다. 아래 초안은 저장소 루트에 `CLAUDE.md`로 저장한다.** 지시 예: "계획서의 T10을 구현해. 완료 조건을 모두 확인하고 결과를 보고해." 처음 한 번은 "계획서의 T00 섹션을 읽고 요약해"로 접근되는지 확인한다. 접근이 안 되면(비공개 문서라 같은 claude.ai 계정 로그인과 문서 읽기 도구가 필요) 이 문서를 마크다운으로 내보내 `docs/PLAN.md`로 두고 같은 방식으로 지시한다.

계획서 링크: https://claude.ai/code/artifact/86ca1610-52e1-45e1-a819-912fb2e77d96

### 개발 환경 (사용자 준비 사항)

- Windows 11 PC에서 Claude Code 실행 (WPF·Win32는 Windows에서만 빌드·실행됨)
- .NET 8 SDK, Git, (선택) Visual Studio 2022

### CLAUDE.md 초안

```markdown
# Screen Annotation

Windows 11 화면 판서 앱. 전체 기획·설계는 계획서(https://claude.ai/code/artifact/86ca1610-52e1-45e1-a819-912fb2e77d96, 접근 불가 시 docs/PLAN.md). 태스크는 계획서의 "태스크 트래커"와 상세 섹션을 따른다.

## 기술 스택
- .NET 8 (net8.0-windows10.0.19041.0), C#, WPF, MVVM(CommunityToolkit.Mvvm)
- DI: Microsoft.Extensions.DependencyInjection
- Win32: CsWin32 (NativeMethods.txt에 API 이름 추가). 직접 DllImport 작성 금지
- 캡처: Vortice.Direct3D11/DXGI (Desktop Duplication), 대체 Windows.Graphics.Capture
- UIA: Interop.UIAutomationClient (COM)
- 테스트: xUnit + FluentAssertions

## 아키텍처 규칙
- Core는 WPF·Win32·System.Drawing을 참조하지 않는다
- Win32 호출은 ScreenAnnotation.Windows 프로젝트에만 둔다
- 판서 좌표는 항상 "모니터 로컬 물리 픽셀"로 저장한다. DIP 변환은 렌더 직전에만
- 판서 데이터 변경은 IAnnotationCommand를 통해서만 한다
- UI 스레드에서 50ms 이상 걸릴 수 있는 작업(캡처 인코딩, UIA 질의, OCR)은 백그라운드로

## 작업 방식
- 한 번에 태스크 하나. 시작 전 계획서에서 해당 태스크의 범위·완료 조건을 다시 읽는다
- 완료 조건 중 자동 테스트 가능한 것은 테스트로 작성한다
- 사람이 눈으로 확인해야 하는 항목은 docs/checks/<태스크ID>.md에 확인 절차를 적고 결과 칸을 비워 둔다
- 태스크 범위 밖 변경이 필요하면 구현하지 말고 보고한다
- 끝나면: dotnet build, dotnet test 통과 확인 → 변경 요약, 남은 이슈 보고 → 커밋 메시지 "T<ID>: <요약>"

## 빌드·실행
- dotnet build ScreenAnnotation.sln
- dotnet test
- dotnet run --project src/ScreenAnnotation.App
```

## M0·M1 태스크 상세

**M1의 목표는 "판서 없이" 켜기·끄기와 Ctrl+클릭 인식이 실제로 되는지 확인하는 것이다.** 각 태스크는 범위 / 산출물 / 완료 조건으로 적는다.

### T00 — 솔루션 골격

- 범위: `ScreenAnnotation.sln`, 프로젝트 7개(App, Core, Rendering, Windows, Recognition, Storage, Watchdog) + 테스트 3개(Core.Tests, Rendering.Tests, Windows.IntegrationTests). 프로젝트 참조는 "솔루션 구조" 그림대로
- `Directory.Build.props`: Nullable enable, TreatWarningsAsErrors, LangVersion latest
- App: 매니페스트 `PerMonitorV2`, DI 부트스트랩(`AppBootstrapper`), 이름 있는 Mutex로 단일 실행, 트레이 아이콘(메뉴: 종료)
- 완료 조건: `dotnet build`·`dotnet test` 통과, 실행 시 창 없이 트레이 아이콘만 뜸, 두 번째 실행은 즉시 종료

### T01 — 로깅·성능 계측

- 범위: `Microsoft.Extensions.Logging` + 파일 로그(`%LOCALAPPDATA%\ScreenAnnotation\logs`, 일 단위, 7일 보관). `PerfScope`(Stopwatch 기반, 이름·소요 ms 로그) 유틸
- 완료 조건: 시작·종료 로그 기록, `PerfScope` 단위 테스트

### T02 — 설정 저장소

- 범위: `Settings` 모델(핫키, 도구별 색·굵기, 사라지는 시간 2.5초, 저장 위치 `사진\ScreenAnnotation`), `SettingsRepository`(`%APPDATA%\ScreenAnnotation\settings.json`, `.tmp` 후 `File.Replace`), 손상 시 기본값 + 손상 파일 백업
- 완료 조건: 왕복 직렬화·손상 파일 처리 단위 테스트

### T10 — 모니터 서비스

- 범위: `MonitorInfo`(Key, 물리 경계, 작업 영역, DPI X/Y, 주 모니터 여부). Key는 `QueryDisplayConfig`의 `monitorDevicePath`. `WM_DISPLAYCHANGE`·`WM_DPICHANGED` 시 `MonitorsChanged` 이벤트
- `CoordinateService`: 전역 ↔ 모니터 로컬 픽셀 ↔ DIP 변환
- 완료 조건: 음수 좌표·150% DPI 변환 단위 테스트, 실행 시 로그에 모니터 목록 출력

### T11 — 전역 핫키

- 범위: 숨은 메시지 창에서 `RegisterHotKey`(기본 Ctrl+Shift+Space, 설정값 사용). 등록 실패 시 트레이 풍선 알림. `HotkeyPressed` 이벤트
- 완료 조건: 다른 앱이 포그라운드일 때도 이벤트 발생, 실패 경로 수동 확인 절차 `docs/checks/T11.md`

- 완료 조건: 4K 1장 합성·저장 500ms 이내, 저장 이미지가 화면에 보이던 것과 같음(확대 상태와 무관)

### T51 — 끄기 확인창

- 범위: 판서가 없으면 바로 끔. 있으면 커서 모니터 가운데에 확인창: 저장(Enter) / 버리기(N) / 계속 판서(Esc). 확인창에서 Ctrl+Shift+Space → 버리고 끔. 저장 = T50과 동일, 이후 끔
- 완료 조건: 네 경로 모두 동작, 확인창이 떠 있는 동안 판서 입력 무시

### T52 — OCR 서비스·영역 OCR

- 범위: `IOcrService` + `WindowsMediaOcrService`(한국어·영어, 언어팩 없으면 `IsAvailable=false` + 설치 안내). Ctrl+클릭 텍스트 2차 경로 연결(클릭 주변 영역 → 단어 상자 → 줄·문단 묶기). Ctrl+드래그 영역 선택 → 인식 → 글자 클립보드 복사 + HUD 표시
- 완료 조건: PDF 뷰어·원격 화면에서 Ctrl+클릭 텍스트 인식 동작, 인식 중 판서 지연 없음

### T53 — 이미지 2차 인식

- 범위: `ImageRegionDetector` — 클릭 주변 바깥 링 최빈색 = 배경 추정 → 배경과 다른 픽셀 마스크 → 팽창 → 클릭 지점 포함 연결 영역 → 경계 사각형. 크기 상한(모니터의 80%) 초과 시 실패 처리. 순수 C#(OpenCV 미사용)
- 완료 조건: T43 데이터셋의 PDF·이미지 화면에서 성공률 리포트

### T54 — 도형 자동 보정

- 범위: 펜 획 끝에서 버튼을 누른 채 0.5초 멈추면 `ShapeRecognizer` 판정(직선·사각형·타원, 기준은 "도형 보정 판정" 섹션) → 해당 도형으로 Replace. 판정 실패 시 원본 유지. 그냥 떼면 판정하지 않음
- 완료 조건: 판정 단위 테스트(손그림 샘플), 보정 후 Undo로 원래 획 복원

### T60 — 설정 화면
